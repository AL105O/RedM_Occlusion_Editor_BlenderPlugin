# RedM Occlusion Editor — Blender Plugin

**Edit RedM YMAP occlusion geometry directly in Blender 4.5, using CodeX for native YMAP conversion.**

The **RedM Occlusion Editor** is a Blender add-on for importing, editing, and exporting the occlusion meshes contained in a Red Dead Redemption 2 / RedM YMAP. Its workflow is designed to keep the rest of the YMAP XML intact while you work on its occlusion geometry.

> [!IMPORTANT]
> This add-on edits **YMAP XML**, not native binary `.ymap` files directly. Use **CodeX** to convert between the native format and XML.

## Requirements

- **Blender 4.5**
- **CodeX World Editor** for YMAP XML export and native YMAP reconstruction
- A YMAP exported as XML through CodeX
- The RedM Occlusion Editor Blender add-on

## Installation

1. Download the add-on files from this repository.
2. In **Blender 4.5**, install the add-on using Blender's add-on installation workflow appropriate to the downloaded package.
3. Enable **RedM Occlusion Editor** in Blender's add-on preferences.
4. Locate the **RedM Occlusion** tools in Blender side bar.

> [!NOTE]
> Installation details may vary depending on how the add-on is packaged in this repository.

## Workflow

### 1. Export the complete YMAP from CodeX

Open your YMAP in **CodeX World Editor** and export the **entire YMAP** as XML. 
NOTE: the add-on needs the complete field to preserve unrelated YMAP data.

### 2. Import the YMAP field into Blender

In Blender, navigate to:

**RedM Occlusion → Import Entire YMAP Field**

Select the XML file exported from CodeX.

### 3. Edit the occlusion meshes

Modify the imported occlusion meshes in Blender to suit your scene. Keep the geometry intended for export within the add-on's supported workflow.

### 4. Export the edited field to XML

Use the add-on's XML export function to export the updated YMAP field.

The add-on is designed to **preserve unrelated YMAP data** while updating the edited occlusion meshes.

### 5. Rebuild the native YMAP in CodeX

Import the edited XML using **CodeX's existing XML import** functionality, then rebuild the native `.ymap` file.

### Important: Keep the original filename suffix

Preserve the original filename and extension pattern generated by CodeX. The usual suffix is:

```text
.ymap.rsc.xml
```

For example:

```text
example.ymap.rsc.xml
```

Avoid renaming the XML to a generic `.xml` name if CodeX expects the original suffix.

## Workflow at a Glance

```text
Native .ymap
    |
    v
CodeX: Export entire YMAP as XML
    |
    v
Blender 4.5: RedM Occlusion → Import Entire YMAP Field
    |
    v
Edit occlusion meshes
    |
    v
Blender: Export updated YMAP field to XML
    |
    v
CodeX: Import XML and rebuild native .ymap
```

## Best Practices

- **Back up the original YMAP** before making changes.
- **Export the entire field** from CodeX, not an isolated mesh.
- **Preserve CodeX's filename suffix** (usually `.ymap.rsc.xml`).
- **Validate the rebuilt YMAP** in your RedM environment before replacing a working version.
- Keep a copy of the exported XML while testing your edits.
